# dislop Agent Skill 专项优化与五轮迭代复盘

基于 [PRODUCT.md](../../PRODUCT.md) 的最新定位，`dislop` 面向两类核心调用方：第一顺位是写入代码库文档与前端界面的编程 Agent，第二顺位是起草报告、Word（`.docx`）与幻灯片（`.pptx`）的办公 Agent。Skill 层坚持开源零脚本、按需读取单张纯文本参考卡，离线工作时也能独立生效；若宿主已挂载本地 CLI 或云端 MCP 工具，再把提示词规则串进检查与修复闭环。

## 1. 基线问题与第一轮诊断

第 1 轮在两个实测模型（`gemini-3.5-flash` 与 `qwen3.8-flash`）上对照评测旧版 `v0.7.1` Skill（正文 2,575 字节 + 4 张纯英文参考卡），同时请独立跨厂商盲审模型对输出做红队诊断，暴露出四处结构性短板：

- 触发与选卡偏低：`v0.7.1` 在 `gemini-3.5-flash` 上触发 F1 只有 `83.1%`，4 张混装卡的正例选卡准确率低至 `52.6%`，隐式起草 README、CLI 报错文案与英文随笔经常漏触发，合规通知与办公文档也容易选错卡。
- 描述壳挤压上下文并混入无关语种：旧版 `SKILL.md` 塞了长段 MCP JSON 配置与营销数字，且中英文共用同一套英文长卡，既拉高单次加载长度，也容易把英文模板词带进中文产出。
- 无工具宿主的空喊工具名：无条件写出工具调用步骤后，没挂载任何工具的纯对话宿主或评测沙箱里，弱模型会把工具名原样当成结果返回。
- 底层否定边界极性缺陷：实测核验顺带揪出规则引擎 `FACT_QUALIFIER_PATTERNS` 否定前缀问题（`no less than` 与 `不低于`、`不少于` 被误判成上限），随后在 Node 内核与 Python 引擎同步修完并补齐一致性单测。

## 2. 五轮迭代路径

围绕路由精准度、信息保真度、去 AI 味洁净度、干净原稿保真度与单次上下文负载 5 个维度，共推进了 5 轮完整闭环实验，每轮都在独立盲审与全量自动化回归之后再改下一轮规则：

| 轮次 | 核心改动与评测修复 | `gemini-3.5-flash` (`skill_cand`) | `qwen3.8-flash` (`skill_cand`) | 跨模型盲审结果（非平局） |
|---|---|---|---|---|
| 第 1 轮 | 冻结 `v0.7.1` 基线；修复内核否定边界极性 bug；构建 `no_skill`/`skill_v0` 基线 | F1 `83.1%`，选卡 `52.6%`，Overall `98.1`（`NoVeto 100%`） | F1 `93.0%`，选卡 `71.1%`，Overall `95.5`（保真跌至 `83.3%`） | 发现旧卡漏改与保真误伤问题 |
| 第 2 轮 | 重构为轻量 `SKILL.md` + 中英分离 8 张按文体参考卡；剥离 MCP JSON 与营销数字；接入 `skill_cli` 组 | F1 `100.0%`，选卡 `100.0%`，Overall `98.8`（30 题） | F1 `100.0%`，选卡 `92.1%`，Overall `98.2`（`NoVeto 96.7%`） | 发现对照示例与样本主题重合风险 |
| 第 3 轮 | 彻底剥离样本重合句，补全三段对照与逐句可追溯纪律；扩充扩展审校集与 Holdout v1（共 38 题） | F1 `100.0%`，选卡 `94.7%`，Overall `99.1`（Holdout `100.0`） | F1 `100.0%`，选卡 `78.9%`，Overall `96.9`（遇 `dislop_check` 裸回显） | 胜 `skill_v0` **20–4–6**；胜 `no_skill` **23–1–2**（换位一致率 6/6） |
| 第 4 轮 | 将 `§4` 改为条件式工具调用并禁止输出裸命令；新增 CLI/跨语种路由与 Holdout v2（40 题）；捕获 `8192` 思考截断与 `three` 匹配 bug | 路由双 `100.0%`，裸工具回显清零；2 题受 `max_tokens` 截断 | 选卡升至 `92.9%`，跨语种持平，个别长文待收敛 | 定位思考上限与 `ho-en-05` 拼写原子 bug |
| 第 5 轮 | 提升推理模型 `max_tokens` 至 `16384`，消除随笔卡计字数暗示；按 `minChars=180`/`minWords=85` 严格重算 | F1 `100.0%`，选卡 `100.0%`，Overall **`98.5`**（CLI 组 **`99.5`**，事实全对 `39/40`） | F1 `100.0%`，选卡 `100.0%`，Overall **`98.5`**（`NoVeto 90.0%`，较无 Skill 提升 `7.8` 分） | 胜 `skill_v0` **13–8–9**；胜 `no_skill` **18–4–4**（换位一致率 6/6） |

第 5 轮在线跑完后，结合该轮盲审指出的细节，我们在离线阶段进一步清理了 5 张参考卡三段对照中的额外臆测词（`office.md`、`office.zh-CN.md`、`web-ui.md`、`web-ui.zh-CN.md`、`work-docs.md`）以及 `essay.zh-CN.md` 中 2 处与留出集指令重合的措辞，并把题目 `instruction` 字段一并纳入 `checkCardContamination` 全卡防泄漏扫描，离线全量回归与规则零告警全部通过。

## 3. 盲审救回的典型陷阱（只看自动分发现不了的问题）

这套实验里真正决定最终 Skill 质量的改动，多数不是自动总分告诉我们的，而是盲审对照和人工抽检揭出来的：

- 自动高分容易掩盖无中生有。多轮自动综合分拿到 `100` 且 `NoVeto` 的样本，在盲审里照样会因为凭空补出故障根因、测试结论或现场环境描写而被判负，因此正式报告不再把总分放第一，而是以 `NoVeto%` 和跨模型盲审胜率作为主要判断依据。
- 干净对照例句自身不能多添词。第 3 轮到第 5 轮的审查反复说明，只要参考卡里的改干净例句比原句多出一个名词（例如把 `valve tuning` 写成 `valve timing`，或在幻灯片要点里顺手补出原稿没写的排查步骤），模型就会模仿在删套话时顺带编造业务动作；把示例严格缩回原句事实真子集后，这类偏移才收敛。
- 粉红大象提醒会拖垮思考预算。早先在随笔卡写明禁止插入行内计字数后，推理模型反而在思考阶段逐字编号校验字数，在第 4 轮耗尽 `8192` token 上限导致思考文本外泄；改用正面表述并把思考上限放到 `16384` 后，第 5 轮 `320` 条产出零截断。
- 保真指标与跨文件上下文边界。短段落若包含整句直接引语，外围叙述就算被改写，整段字面相似度依然可能跨过 `0.80` 门槛；跨页幻灯片结构以及只写在文件名里的组件词（例如 `redis-postmortem.md`）也需要在文档中单独标明边界。

## 4. 开源可用结论与后续边界

整理后的 Skill 保持纯 Markdown 交付与零外网依赖，按目标输出语言隔离为 8 张参考卡：首页摘要与正文入口共占约 `864` token，单次命中按需加载约 `780` token，既压低了日常挂载的上下文占用，也让两个主流快速模型在 `32` 条中英文混杂与跨语种路由用例上达到双 `100.0%` 准确率与零误触发。评测脚本、脱敏结果与已知测量局限全部收拢在 [Agent Skill 评测报告](../../benchmarks/SKILL-BENCHMARK.md)，后续规则迭代前只需运行 `npm run bench:skill` 即可拦截参考卡泄漏、XML 失衡或极性倒转问题。
