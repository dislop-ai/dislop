# `dislop` 商业模式、护城河飞轮与 Open-Core 边界设计

日期：`2026-11-22` · 状态：战略设计基线（关联 `ROADMAP.zh-CN.md` 与独立闭源云端 `dislop-cloud`）

这份调研回答三个直接影响项目走向的问题：纯脚本和词表没有壁垒时真正的复利护城河在哪、三层信任架构的开源与闭源边界怎么切、以及用 Google Cloud / Gemini 跑托管大模型后台的成本与防刷账怎么算。

## 1. 行业对标实测（2025–2026 公开定价与护城河对照）

我们横向核对了 9 个与 `dislop` 形态最接近的真实产品，并重点对照了四类规则引擎与内容治理先例（`Semgrep` vs. `Vale`、`Acrolinx`、`Rspamd/EasyList`）。

### 1.1 开源内核与规则生态（为什么 `Semgrep` 跑通了而纯词表没有）

| 项目 | 开源协议 | 商业化结构 | 护城河与付费转化点 |

## 2. 核心判断：真正的复利护城河飞轮与三层信任边界

### 2.1 为什么纯脚本、平铺词表或独立小模型本身都不是护城河

如果把竞争力押在单一资产上，都会迅速失效：
1. **纯静态脚本与平铺禁词表**：容易被 10 分钟抄走，且避开旧词表后检出率立刻归零（`v1` 词表在 `text-hard-v2` 上召回跌至 `4.2%`），硬加单词黑名单又会误杀正常技术文档。
2. **独立小模型**：在没有硬负例约束的情况下，跨领域误报率居高不下（实测微型神经网络在本仓真实段落误报达 `15.1%`），且无法给作者可执行的修改定位。
3. **薄 LLM 代理套壳**：Coding Agent 用户手里已经有顶级模型订阅，不会为薄代理买单。

**`dislop` 真正的复利护城河飞轮由五环咬合而成**（L0–L3 修复边界与闭源评估架构详见 [agent-repair-boundaries-eval-and-dehedging.zh-CN.md](./agent-repair-boundaries-eval-and-dehedging.zh-CN.md)）：
1. **困难负样本对抗基准（`dislop-bench v2`）**：持续沉淀跨中英文、跨模态、零误报要求的对抗正负样本（核心 112 样本 + 多角度 154 样本 + 18 组端到端改稿任务 + `stealth-vapor-v1`），任何规则与模型改动不通过基准门禁绝不上线。
2. **6 维度模式与护栏标准（`packs/` + `patterns/`）**：把 53 条内置规则与 65 条结构化反模式沉淀成带防误报护栏、检查问题与 `bad -> trap -> good` 三态对照的开放标准。
3. **垂直场景规则包**：覆盖通用工作简报之外的工程 RFC/复盘（`engineering-spec`）、合规外发（`regulated-comms`）与高管演示文稿（`executive-deck`），直击具体职业岗位的真实返工痛点。
4. **成本套利自愈云（`dislop-cloud`）**：用确定性诊断 + 内部数字与边界限定词保真护栏 + 自动手术修复闭环，把轻量低价模型（如 `Gemini 3.1 Flash-Lite`，约 `\$0.09 / 1k` 次调用）的改稿得分从裸 Prompt 的 `82.7` 拉到 `98.5 / 100`，形成既快又便宜、还比用户自己写 Prompt 更稳的云端体验。
5. **闭源防改坏净增益评估与持续校准飞轮**：由不公开的原子布尔清单与跨厂商换序盲测对 `Before vs. After` 改写进行事实完整度与语域保真验收；全档位坚持用户文稿零训练，仅依托闭源对抗基准、脱敏合成改坏集、用户 Opt-in 纠错反馈与人工金标 Cohen's Kappa 持续升级裁判权重，防止外部 Agent 刷分（Goodhart 过优化）。

### 2.2 三层清晰信任边界（零规则 DLC，开源与云端干净解耦）

开源 CLI 全部规则包免费开放（Zero Rule DLCs），主仓库也只维护本地检测与改写核心，三层产品按不同运行边界划分为三个清楚的信任层级：

| 信任层级 | 仓库与许可 | 包含内容 | 隐私与商业定位 |
|---|---|---|---|
| **第 1 层：本地 Agent Skill** | `dislop-ai/dislop`（Apache-2.0） | `skills/dislop/SKILL.md` + 8 张中英文 `./references/*.md` 参考卡 | 全程 `0` 联网、`0` 外发抓取审批，动笔前直接预防 AI 腔与模板味。 |
| **第 2 层：开源零依赖 CLI 与本地 stdio MCP** | `dislop-ai/dislop`（Apache-2.0） | Node/Python 零依赖引擎（包体 `< 250 KB`）、全部 **7 套内置规则包（53 条规则）**、65 条模式库、随包 `14.6 KB` Pocket ML（`models/pocket-slop-v1.json`）、6 工具本地 stdio MCP（兼容旧别名）、离线个人文风提取（`dislop voice`）、硬件感知选装本地 GGUF 小模型（`dislop setup` / `deslop --local`）、浏览器离线工作台、90 条 `Awesome Anti-Slop` 与 `dislop-bench v2` | 全程本地运行、零规则 DLC、默认 `0` 上传，拿下开源口碑、行业标准与企业安全准入。 |
| **第 3 层：闭源托管云端与远程 HTTP MCP** | 独立私有仓 `dislop-cloud`（`https://dislop.com/mcp`） | 付费级零训练 Gemini 分层路由、哈希 `dslp_*` 账号体系、额度计量与防刷网关、`dislop_review`（1 额度）、自愈 `dislop_deslop`（2 额度，含内部数字与限定词保真护栏）、云端 `dislop_voice_extract`（2 额度）、防改坏评估服务（`dislop_eval` / `dislop_verify_edit`），以及后续 `.docx`/`.pptx` 原排版洗稿、VLM 视觉审校与团队文风库 | 靠**免本地环境直连 + 1.2 秒高性价比自愈改写 + 闭源防改坏净增益验收 + 难自建的多模态/原排版重能力 + 团队治理**实现可持续收入。 |

### 2.3 全球英语主战场与中文办公场景的同核双面承接

在保持单一代码库、单一域名 `dislop.com` 与统一云端额度账本的前提下，技术底座、文档与商业主线统一以**英语（全球）市场为优先**，中文市场在同源内核上做轻量分面兼容：

- **英语（全球）市场作为核心主战场**：海外个人写作者与工程/内容团队对写作质检工具（`\$12/月` Pro）和团队 PR 规范席位（`\$29/席位/月` Team）付费习惯成熟，且全球 Agent 注册表与主流大模型工具索引均以英语为主导，与现有海外云节点和 Stripe 美元结算天然匹配。英文根站（`/`）首屏优先突出 Agent 一键接入、CLI、CI 门禁、远程 MCP、Google 登录与信用卡订阅。
- **中文市场作为冷启动跳板与办公洗稿现金流侧翼**：前期依托中文开发者社区的高采纳密度快速积累开源口碑；商业化阶段则面向不配置本地开发环境的日常办公人群，在中文子路径（`/zh/` 及无代码办公着陆页）重点突出网页直传与 `.docx`/`.pptx` 保留原排版去味导出，并在同一账号与支付底座上优先展示邮箱验证码登录、跨境支付宝/微信支付与无月租压力的 `\$10` 按量额度包。

## 3. Google Cloud / Gemini 成本账与隐私红线

### 3.1 隐私红线：绝不用免费层跑公网用户稿件

公开条款显示，Google AI Studio 免费层的请求内容可能被用于模型改进；而 **Google Cloud Vertex AI 付费层**与 **AI Studio 付费层**明确不将客户数据用于训练。`dislop` 面向的是未发布的技术方案、汇报材料和商业文档，官方托管后台 `dislop-cloud` 必须运行在**不用于训练数据的付费端点**，并做到服务端零稿件落盘日志（详见 `https://dislop.com/privacy.md`）。

### 3.2 单次成本与毛利测算（基于 2025–2026 公开单价）

以一份 1,500 字中文/英文稿件（约 2,500 输入 tokens + 1,500 输出 tokens）为基准：

| 调用类型 | 推荐模型档位 | 参考公开单价（每百万 tokens） | 单次成本估算 | 消耗权重 |
|---|---|---|---|---|
| `dislop_check` | 确定性引擎（无 LLM） | \$0 | **\$0.0000** | `0 credits` |
| `dislop_review`（三阶审校） | Flash-Lite 档（轻量快速） | 输入 \$0.10 / 输出 \$0.40（缓存读 \$0.01） | **约 \$0.00085** | `1 credit` |
| `dislop_deslop`（自愈改写 + 内部保真护栏） | Flash-Lite / Flash 档 | 实测约 `\$0.09–\$0.36 / 1k` 次 | **约 \$0.0001–\$0.0045** | `2 credits` |
| `dislop_visual_audit`（规划中：页面/PPT 渲染 + VLM） | 视觉 Flash 档 + 无头渲染 | 含截图渲染与多模态 tokens | **约 \$0.008–\$0.015** | `5 credits` |

**毛利与免费获客预算**：
- 官方提供本地无限次离线检查与登录后每月 `30` 次免费云端额度，即使每月承载 **10,000 次免费调用**（70% `review` + 30% `deslop`），月模型成本仍低于 **\$20**，是极低成本的精准获客漏斗。
- 对标 **Pro（\$12/月，1,500 credits）** 与 **按量包（\$10，800 credits）**，即使重度用户用满全部额度，按分层路由测算模型成本约 **\$0.85–\$2.70**，**毛利率稳定维持在 78%–88% 以上**。

### 3.3 公网防刷五道硬护栏

| 防护层 | 具体配置 | 防什么 |
|---|---|---|
| 独立项目与独立 Key | 单独建 Google Cloud 项目与专用付费 API Key | 与个人或其他业务完全隔离，出问题一键吊销。 |
| 硬性配额上限（Hard Quota） | 控制台设 RPM 与日额度硬顶 + 服务端全局日限额熔断 | 防止分布式脚本撸穿账单。 |
| 登录后开启云端调用 | 本地离线检查不限次免登录；云端审校与改写需通过邮箱 6 位验证码或 Google 登录解锁 `30 credits/月`，上游报错自动原子退还额度 | 拦截匿名脚本直接刷付费接口，同时沉淀高意向用户 |
| 体积、超时与脱敏 | 单请求上限 `4k / 12k / 50k` 字符（按套餐分档）、上游超时熔断、日志严格不落盘原稿与密钥 | 防止大包打爆内存或泄露用户隐私。 |

## 5. 真正拉开差距的五大云端增值服务

开源层已经把离线检测、7 套规则包和本地 Skill 做透，闭源云端只押注**本地很难配好、需要闭源基准防刷分、或需要持续沉淀状态**的五项能力：

| 增值能力 | 解决什么痛点 | 为什么用户愿意付费而不自己搭 |
|---|---|---|
| 原排版文档一键洗稿（`.docx` / `.pptx` Round-Trip） | 拖入 Word 或 PPT，逐段去 AI 味并经内部保真护栏校验数字后，保留原样式、母版、图表和目录重新导出 | 非技术用户付费意愿最强的痛点，不需要碰 CLI 或 API Key。 |
| 网页与 PPT 视觉多模态审查（Visual Anti-Slop） | 后台无头渲染 HTML / `.pptx` 为真实截图，再用 VLM 审校版式拥挤、模板审美和连续同版式 | 需要重渲染环境与多模态调度，个人几乎不会本地维护。 |
| 个人与团队文风库（`dislop.voice/1` 云端托管） | 导入作者或公司历史好文，跨设备与团队共享句长节奏、用词偏好与禁词边界 | 让改稿保留“自己/品牌的声音”，且随团队使用越用越粘。 |
| 经 `dislop-bench v2` 验证的成本套利自愈流水线 | 确定性预检 → 分文体改写 → 内部数字与限定词保真护栏 + 二/三阶探针复检 → 失败自动手术修复 | 用轻量模型跑出 98–100 分效果与 1.2 秒低延迟，直接省掉调 Prompt 与换高价模型的成本。 |
| 防改坏评估与净增益验收云（`dislop_eval` / `dislop_verify_edit`） | 针对 Coding / 办公 Agent 自动改稿，校验 `Before vs. After` 原子事实精召率、语域漂移与跨厂商换序盲测净增益 | 闭源不公开裁判权重与对抗基准可防 Goodhart 刷分；严格零训练，仅用闭源对抗集、Opt-in 纠错与人工金标 Kappa 校准。 |

## 6. 分阶段验证路线
