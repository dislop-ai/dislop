# 反趋同研究报告：可控随机性、个性化声纹与正向差异化参考体系

> 快照日期：2026-11-21 · 关联文档：[anti-slop-landscape-2026.zh-CN.md](./anti-slop-landscape-2026.zh-CN.md) · [ROADMAP.zh-CN.md](../../ROADMAP.zh-CN.md) · [design-system.zh-CN.md](../design-system.zh-CN.md) · 附属结构化草案见 [positive-divergence/](./positive-divergence/)。本文严格区分「经一手论文、GitHub API 或公开网页实测核验的事实」与「面向 `dislop` 的工程设计及产品假设」。

## 执行摘要

AI 味的表层症状是高频套词、否定转折口号和蓝紫粉渐变卡片，根源则是对齐后大语言模型在统计上的**模式坍缩（mode collapse）与均值回归**。现有反 AI 味工具（包括 `dislop` 的确定性规则检查与模式库扫描）主要承担「负向排除」职责：划清 AI 残留底线、删掉模板废话。但仅靠负向排除存在天然上限——把第一代套路全部删净之后，模型往往滑向平庸安全的统计均值，或坍缩到第二代新套路（例如统一的暖米白卡片模板、连续短句口号）。（注：本报告中提出的离线声纹提取 `dislop voice` 已在 `v0.6.0` 落地于 CLI、本地 MCP 与官网工作台，其余 `taste/1`、`compare`、`drift` 仍为远期提案。）

本报告围绕与反模式识别互补的另一半能力——**「正向建构、可控差异化与个性化（Positive Patterns, Controlled Divergence & Personalization）」**——开展跨学术界、设计界与写作工程的深度研究，得出五项核心判断：

第一，**趋同不仅发生在单模型内部，也跨模型存在**。NeurIPS 2025 最佳论文 *Artificial Hivemind*（Jiang 等人，2025，[arXiv:2510.22954](https://arxiv.org/abs/2510.22954)）证实，不同厂商的模型在开放式任务上会独立坍缩到高度重叠的思路。单纯切换模型或拉高采样温度无法解决趋同，有效干预必须上移到结构约束、分布显式展开与多路径比选。

第二，**「有差异但不失真」的关键在熵控分区，而非全局调参**。事实锚点（数值、限定词、日期、链接、代码、引用与 WCAG/版面底线）必须保持零熵锁死；随机性与差异化只能注入中层的布局拓扑、叙事骨架、论证切入点与句式节奏，再通过确定性门禁剪除怪异失控的候选。

第三，**非主流设计复用的核心是抽离「结构语法」，而非整站照抄**。截至 2026-11-21，前端侧 `VoltAgent/awesome-design-md`（128,462★）与 `anthropics/skills`（198,165★）已普及品牌级 `DESIGN.md` 注入，但直接照抄少数明星 SaaS 品牌反而催生了第二代视觉同质化。更持久的路径是从独立字厂、书展出版物、瑞士排版与编辑部案例中提炼人机共用的**正向设计参考卡（`dislop.taste/1`）**，并绑定静态可检断言。

第四，**个性化写作应告别「形容词崇拜」，转向「可量化声纹 + 三维骨架范本」**。要求模型「模仿某作家」往往产出廉价漫画化文风。可行方案是用纯本地确定性统计从个人历史原稿提取**声纹画像（`dislop.voice/1`）**（句长变异系数、段落分布、标点频谱、连接词克制度与个人避讳），再配合按「结构骨架 × 信息密度 × 表达视角」分类的正向范本，同时用仓内跨文档趋同检测防范二阶模板化。

第五，**`dislop` 的产品化应严守「零 LLM 核心、双向协议协同」定力**。不要把 `dislop` 改造成调用大模型代写的聊天套壳。正确架构是用确定性工具承担四件擅长的事——离线提取声纹、编译正向约束上下文、多候选过滤比选、跨文档趋同预警——让上游宿主 Agent 负责发散生成，让 `dislop` 负责正向牵引协议与负向事实底线验收。

## 1. 反趋同的底层机制：可控随机性与差异化生成

### 1.1 为什么对齐后的 LLM 必然发生均值回归

多组独立实证研究共同锁定了生成式内容同质化的因果链条：

| 实证研究 | 发表载体与年份 | 核心发现与量化证据 | 对工程设计的启示 |
|---|---|---|---|
| Padmakumar & He（[arXiv:2309.05196](https://arxiv.org/abs/2309.05196)） | ICLR 2024 | 受控写作实验对比独立写作、基座 GPT-3 与 RLHF 对齐后的 InstructGPT：仅 InstructGPT 引起显著的群体词法与内容多样性下降，且下降主要由模型贡献片段驱动 | 趋同的直接推手是后训练偏好对齐（RLHF），而非预训练知识本身匮乏 |
| Doshi & Hauser（[DOI:10.1126/sciadv.adn5290](https://doi.org/10.1126/sciadv.adn5290)） | *Science Advances* 2024 | 创意短篇实验中，借助生成式 AI 能提高单个写作者的成稿评分，但显著压低群体作品整体的新颖度与彼此差异 | 局部单篇看似变好，会掩盖群体层面的表达塌陷 |
| Jiang 等人 *Artificial Hivemind*（[arXiv:2510.22954](https://arxiv.org/abs/2510.22954)） | NeurIPS 2025 Best Paper（Datasets & Benchmarks） | 基于 `INFINITY-CHAT` 评测揭示双层同质化：同一模型反复输出相似结构（intra-model repetition），且不同厂商模型独立收敛到相近思路（inter-model homogeneity） | 仅靠多模型轮换或投票集成无法自动获得认知与风格多样性 |
| Zhang 等人 *Verbalized Sampling*（[arXiv:2510.01171](https://arxiv.org/abs/2510.01171)，开源仓 `CHATS-lab/verbalized-sampling` 828★） | 2025（预印本与开源实现） | 指出人类偏好标注中的**典型性偏差（typicality bias）**是数据层根因：标注员系统性偏爱熟悉、流畅、符合直觉的回答，使对齐过程惩罚了预训练期习得的长尾表达 | 预训练模型内部仍保留丰富分布，推理期可通过提示重构重新唤醒 |

综合上述证据可见，「去 AI 味」之所以只靠禁词表永远追不上，是因为禁词表只堵住了分布峰顶的几个词汇出口；只要底层采样机制仍在追逐“单次最安全、最典型的唯一答复”，模型就会立刻坍缩到紧邻峰顶的次高频套路。

### 1.2 四层反趋同干预谱系与工程边界

社区与学术界围绕对抗模式坍缩已形成四层干预手段，从底层 Token 采样逐级上移至结构发散与演化筛选：

| 干预层级 | 代表方法与出处 | 作用机制 | 优势 | 工程短板与失效边界 |
|---|---|---|---|---|
| **L1：Token 级解码重塑** | `Min-P`（Nguyen 等人，ICLR 2025 Oral，[arXiv:2407.01082](https://arxiv.org/abs/2407.01082)）；`Locally Typical Sampling`（Meister 等人，TACL 2023，[aclanthology.org/2023.tacl-1.7](https://aclanthology.org/2023.tacl-1.7/)） | `Min-P` 按最高概率 Token 的相对比例（$p \times P_{\max}$）动态截断长尾；Typical Sampling 挑选信息量接近条件熵的 Token | 推理零额外轮次，可在较高温度下维持局部语意连贯 | 只扰动局部选词，不改变篇章结构或版面拓扑；且后续有评测研究质疑 `Min-P` 在部分基准上的幅度夸大；商业闭源 API 往往不开放细粒度解码参数 |
| **L2：推理期分布唤醒** | `Verbalized Sampling`（Zhang 等人，2025，[arXiv:2510.01171](https://arxiv.org/abs/2510.01171)） | 不向模型索要“唯一最佳答案”，而是要求其显式列出 5 条不同路径及各自概率估计，并从尾部低概率区间（如 $p < 0.15$）采样 | 免训练、跨模型通用；在诗歌、故事与开放问答上将多样性提升 1.6×–2.3×，且能力越强的模型收益越大 | 输出 Token 成本上升数倍；尾部路径可能混入跑题或偏怪异的候选，需下游筛选机制把关 |
| **L3：结构化创意约束注入** | *Oblique Strategies*（Brian Eno & Peter Schmidt，1975）；*Oulipo* 约束写作（1960）；反默认禁令注入 | 前者通过横向反直觉启发句（如「按表面最不重要的顺序删减元素」）改变立意与视角；后者用刚性形式规则封堵惯性捷径；反默认禁令则直接禁用某品类的前三套模板 | 极低算力成本即可触发结构级变异，人类和 Agent 均容易理解、复现与归因 | 约束过松时模型会忽略指令滑回默认解；约束过死或脱离文体语境时容易写出炫技但难读的怪文 |
| **L4：质量-多样性搜索（QD / Generate-and-Select）** | `MAP-Elites` 档案网格；`Rainbow Teaming`（Samvelyan 等人，NeurIPS 2024，[arXiv:2402.16822](https://arxiv.org/abs/2402.16822)） | 预先定义二维行为特征网格（如「结构骨架 × 视角距离」或「版面密度 × 视觉秩序」），要求多路生成填满不同象限，再按客观质量指标淘汰低分候选 | 将「发散」与「择优」彻底解耦，保证最终呈现给人类的是多个彼此正交的高质量解，而非单点碰运气 | 需要可计算的客观评估器与低摩擦比选界面，否则人类审查 5 份雷同长稿反而增加疲劳 |

一个容易被忽视的工程结论是：**解码参数（L1）决定词表毛刺，结构约束与分布唤醒（L2 + L3）决定立意与骨架差异，质量-多样性筛选（L4）决定成稿下限。** 面向闭源商业模型为主的 Agent 生态，真正可控且跨平台可迁移的主战场在 L2 + L3 + L4 的组合，而不是依赖往往不可配的底层采样器。

### 1.3 核心工程解：三带可控熵边界（Three-Band Entropy Partition）

要同时满足**「有差异但不怪异、有随机但不失真、有个性但不跑偏」**，不能用单一标量（如把 `temperature` 拧到 `1.1`）去赌运气，而应按内容元素的风险属性把生成空间切分为三个明确边界：

```text
原始素材 / 需求简报 + Positive Taste/Voice Card + 确定性 Seed
   │
   ├─► [带 1：零熵锁死带 Zero-Entropy Invariants]
   │     锁定：数字 / 单位 / 限定词(最多·至少·up to) / 日期 / URL / 代码 / 引用
   │          WCAG AA 对比度 / 深色明度阶梯 / 死链禁令 / 幻灯片画布边界
   │     规则：熵预算 = 0，任何候选一旦触碰即由 dislop core/verify 硬淘汰
   │
   ├─► [带 2：受控中熵探索带 Bounded Divergence Band]
   │     发散轴 A（骨架）：Verbalized Sampling / 3 种正交结构骨架（非同义改写）
   │     发散轴 B（约束）：注入 1 条反默认禁令 + 可选 1 条横向视角卡（按 seed 可复现）
   │     发散轴 C（声纹）：限制在 Voice Profile 的句长 CV、段长、标点频谱目标区间内
   │
   └─► [带 3：越界怪异剪枝带 Coherence & Taste Pruning]
         过滤：1) 反模式检测（一阶套话 + 二阶否定转折/短句口号/暖米白回退）
              2) 声纹偏差分（拦截过矫漫画化或跑偏语域）
              3) 候选间结构相似度（去重同质候选）
         输出：2–3 份事实 100% 一致、结构明显差异化的合格清样供人类终选
```

这套分区机制把「创意发散」限制在安全走廊之内：即使带 2 采用高发散的 Verbalized Sampling 或横向约束卡，带 1 的内部数字与锚点保留护栏（`verifyRevision`）也能确保「最多 12 分钟」「p95 = 180 ms」和原始链接在自动改写时不被误删；即使候选在发散时滑向怪异腔调或二阶口号，带 3 也会在呈现给作者前完成剪枝。

## 2. 设计方向：非主流高品位设计谱系、一手参考源与正向设计卡

### 2.1 两代 AI 视觉均值是如何形成的

如 [design-system.zh-CN.md](../design-system.zh-CN.md) 所记录，生成式前端已先后形成两代视觉均值：

第一代均值（2023–2025）源于 Tailwind 模板与常见 SaaS 落地页在训练语料中的压倒性权重——深色底配蓝紫粉霓虹渐变、Inter 居中 Hero、毛玻璃卡片、均等三列功能盒、满屏 `rounded-full` 胶囊标签与 Bento 网格。

第二代均值（2025–2026）则伴随「反默认模板」风潮一起出现。截至 2026-11-21，`VoltAgent/awesome-design-md`（128,462★）将 Linear、Stripe、Vercel 等数十家知名科技品牌的视觉规范提取为 `DESIGN.md`，`anthropics/skills`（198,165★）的 `frontend-design` 技能也广泛普及。当大量提示词统一要求「禁止紫色渐变、做克制的编辑部极简风」时，模型迅速退回到另一套窄带默认解：暖米白底（`#F7F5F0`）配炭黑与朱砂红，或者千篇一律的 Linear 暗黑发光描边。这说明：**仅把少数流行科技品牌做成 `DESIGN.md`，只会把用户从「通用模板」迁移到「明星品牌仿制品」。**

### 2.2 跳出默认 SaaS 模板的六类高品位非主流设计谱系

要让界面、文稿与演示材料具备长期耐看且不随大流的辨识度，必须把参考半径扩大到软件模板之外的平面印刷、独立字厂、书展装帧与工程手册传统：

| 设计谱系 | 核心视觉文法（可结构化编码） | 典型适用场景 | 极易踩中的反面陷阱 |
|---|---|---|---|
| **1. 瑞士国际排版与建筑网格（Swiss Grid / Galley Proof）** | 显式非对称栏栅、`1px` 通栏结构细线、高对比纸白墨黑、等宽坐标与边注、零弥散阴影与微圆角（`0–4px`） | 开发者工具、技术文档、清样工作台与数据报告 | 留白过空导致首屏缺乏操作入口，或为追求极简砍掉状态反馈 |
| **2. 工程仪表与技术手册（Technical Manual / Spec Sheet）** | 源自航空与实验室手册的高密度表单、开启 `tabular-nums` 等宽数字对齐、严格语义化的三色状态体系（红错/蓝告/绿锁）、零营销标语 | 后台控制台、硬件参数页、SLA 监控与发布说明 | 缺乏视觉主次与分组间隔，退化为难以扫读的密麻参数墙 |
| **3. 独立编辑部与长文出版（Independent Editorial）** | 强烈标题/正文级差、衬线阅读正文配清晰行长（英文 ~65ch / 中文 ~36 字）、右侧边注（sidenotes）与非对称图文跨栏 | 深度研究报告、品牌年报、非虚构长文站点 | 过度依赖重型商业网页字体，在弱网或中文环境下回退断裂 |
| **4. 克制新粗野与裸结构主义（Restrained Neo-Brutalism）** | 诚实暴露信息层级、硬边直角、黑白单色加单一高亮色、直给的纯文本导航与索引表格 | 独立工作室、艺术机构、开源实验工具、个人数字花园 | 滥用高饱和荧光撞色、故意破坏点击区与对比度，牺牲基本可访问性 |
| **5. 独立字厂样本与当代书籍装帧（Type Specimen & Book Art）** | 以字重对比、字距微调、段落节奏和纸面比例作为视觉主角，无需插画或 3D 装饰仍能建立强烈记忆点 | 品牌识别页、发布公告、极简作品集、演讲母版 | 仅照搬西文几何大标题，忽略中文汉字视觉灰度偏重与行高需求 |
| **6. 中文现代编排与东方克制审美（CJK Modernist Editorial）** | 严格遵循 W3C CLREQ 标点与混排规范、合理的汉西间距、克制传统纸墨色域、清晰的层级留白与非均等卡片秩序 | 中文长文刊物、文化/设计产品、双语报告与演示文稿 | 退化为古风装饰贴图、过度使用毛笔体导致小字号糊成色块 |

### 2.4 人机共用的正向设计参考卡（`dislop.taste/1`）结构设计

让 Agent 阅读泛泛的视觉描述（例如「请做得像瑞士杂志一样高级」）极易失控；反过来，直接塞入某品牌的完整 CSS 又构成模仿与版权风险。居中且工程可落地的载体是**结构化正向设计参考卡（Positive Design Card）**——同时可读给人类审阅、编译给 Agent 作为生成边界、并交给 `dislop check` 做静态合规复检。

一张完整的 `dislop.taste/1` 卡片由六个必填区块组成（完整可执行示例见 [positive-design-card.example.json](./positive-divergence/positive-design-card.example.json)）：

1. `lineage` & `fit`（血统与边界）：注明参考流派、一手来源 URL、明确「适用媒介」与「禁止误用场景」（例如把高密度工程手册卡明确排除在消费品情感海报之外）。
2. `layout`（网格与空间预算）：量化主栏最大宽度、行长上限（英文 `ch` / 中文字符数）、圆角区间（如 `0–4px`）、阴影政策（如禁用弥散阴影），以及明确的反默认结构约束（例如 `forbidEqualThreeCardHero: true`）。
3. `typography`（字体角色栈）：按「展示标题 / 阅读正文 / 界面控件 / 等宽坐标」定义角色分工、字号比、行高与零外链系统回退栈，确保离网或无商用字体授权时仍保持骨架成立。
4. `colorBudget`（色彩克制与语义预算）：限定中性画布层数、强调色数量上限（如除语义状态色外最多 1 枚主强调色），直接锁定 WCAG 2.2 AA 对比度下限与深色模式表面明度 `L*` 严格递增规则。
5. `densityAndMotion`（信息密度与微交互上限）：规定单屏控件上限、胶囊标签配额、动效时长上限（如 `<= 120ms`）及 `prefers-reduced-motion` 强制遵循。
6. `enforceableChecks`（确定性断言绑定）：将设计卡里的硬约束映射到 `dislop` 可静态扫描的规则与阈值覆盖（例如 `maxBorderRadiusPx`、`forbidGradients`、`maxAccentHues`、`requireTabularNums`）。这样，当 Agent 在多轮修改中悄悄滑回默认 Tailwind 圆角卡片或紫粉渐变时，工具能立刻精准标出违规行号，而不靠肉眼巡查。

## 3. 文案与写作方向：个性化声纹体系与正向范本方法论

### 3.1 为什么「形容词 + 名人模仿」必然产出劣质文风

社区中常见的个性化写作提示词通常长这样：「请用克制、犀利、有洞察力的风格，像 Paul Graham 或鲁迅一样写一段分析」。这类提示词在实践中有三个固定失效模式：

第一，**自知偏差与词义漂移**。人类对自己写法的口头概括常与真实语料相悖；而且“犀利”“克制”在不同模型里映射到的是高概率语料平均态，模型为了证明自己“犀利”，会立刻堆叠否定转折句和三连短句。

第二，**名人特征的廉价漫画化（Caricature）**。模型模仿名人时抓取的往往是最浅表的词汇符号（模仿鲁迅就硬凑「大约的确」「罢了」，模仿海明威就把所有句子砍成五词电报体），反而丢掉了原作者的论证逻辑与观察精度。

第三，**忽略语种底层结构差异**。英文高质量非虚构依赖**形合（hypotaxis）**与主语具象化、主动动词驱动以及显著的句长突发性（burstiness）；中文高质量写作则大量依赖**意合（parataxis）**流水句、自然韵律停顿、具体器物动词，以及对翻译腔抽象主语（如「这一机制的落地为团队带来了……」）的克制。把英文写作规范直接翻译成中文提示词，往往会造出别扭的“翻译腔短句”。

### 3.2 五维可量化声纹画像（Voice Profile）与离线提取管线

要把个人或品牌的真实表达习惯变成可复用、可检验的资产，应将**声纹画像（`dislop.voice/1`）**拆解为五项可测量维度，并优先用零 LLM 确定性脚本从历史原稿提取（完整示例见 [voice-profile.example.json](./positive-divergence/voice-profile.example.json)）：

| 声纹维度 | 确定性可测指标（零 LLM 离线计算） | 语义补充特征（人工确认或单次抽取） |
|---|---|---|
| **1. 节奏与句长分布** | 句长均值 $\mu$、标准差 $\sigma$、变异系数 $CV = \sigma / \mu$、短句/中句/长句三分位占比、段落句数分布 | 是否习惯长句铺陈后接一句短判断收束，或连续平实中等句长 |
| **2. 句法与连接习惯** | 常见路标词与连接词频次（英文 `However/Moreover/Furthermore`，中文 `首先/其次/因此/从而/通过……实现`）、被动语态/「被」字及「的」字小句密度 | 偏好意合短小分句还是主从复合长句；偏好因果前置还是结论前置 |
| **3. 标点熵与停顿签名** | 每千字/每三百词破折号、分号、冒号、括号插话、问号与感叹号频谱 | 括号是否用于补充硬限定条件（而非闲聊抖机灵）；是否几乎不用感叹号 |
| **4. 视角与证据姿态** | 第一人称/团队复数/无主句占比、数字与限定词密度、出处链接与引用频次 | 面对不确定性时如何措辞（例如直白写出样本量与未测边界，拒绝模糊权威背书） |
| **5. 词表签名与个人禁忌** | 高频实词（锚点动词/名词）统计、中英混排术语习惯 | 作者或品牌明确拒用的陈词（写入被 Git 忽略的 `.dislop.local.json`） |

**两阶段离线提取与盲测校准管线**：

1. **输入清洁样本**：收集 5–15 篇作者本人撰写、未经 AI 大幅改写的代表性文稿（按文体分桶，不把周报、技术设计书与随笔混在同一画像里）。
2. **阶段 A（确定性统计基线）**：由本地 CLI 脚本离线解析文本，计算出各维度的实际分布区间（注意是**容许区间 band**，而非死板单点数值，避免机械拼凑字数）。
3. **阶段 B（结构标注 + 盲测判别）**：从样本中抽取 2–3 段能体现行文逻辑的短锚点（每段 80–180 字，经脱敏），与目标区间一起组合成 `voice.json`。随后在一个全新主题上生成测试段，与作者历史段落混排做**盲测判别（Blind Discrimination Test）**：若读者一眼看出刻意模仿痕迹（例如过度频密的短句或生硬口癖），立即收窄或删除对应规则，防止过矫。

### 3.3 正向写作范本库：按「结构骨架 × 信息密度 × 表达视角」建库

比起按名人贴标签，更经得起跨题材复用的是**结构化正向写作范本库（Positive Style Exemplars）**。每一条范本拆解「论证如何起承转合」，而不鼓励照抄辞藻：

| 结构骨架类型 | 典型段落推进路径 | 适配信息密度 | 中文语境关键动作 | 英文语境关键动作 |
|---|---|---|---|---|
| **S1：结论前置 + 证据账本（Decision Brief）** | 1 句核心结论 -> 量化证据与样本口径 -> 明确边界/反例 -> 可执行动作 | 极高（短段 + 表格） | 删掉时代背景铺垫；把 `赋能`、`抓手` 类抽象词换成具体主体与改动指标 | 强主动语态；避免名词化抽象主语；把限定词紧贴数值 |
| **S2：现象切入 -> 误区拆解 -> 机制归因（Analytical Essay）** | 具体观测样本 -> 指出流行直觉为何失效 -> 给出实证机制 -> 推导工程取舍 | 中高（论点段 + 对照） | 用自然意合流水句推进因果，避免「首先/其次/总而言之」机械框架 | 维持高句长变异系数；用具体动词替代 `-ing` 尾部悬垂总结 |
| **S3：现场切片 + 细节留白（Field Note / Non-fiction）** | 时间/地点/具体器物动作 -> 人物原话或客观观测 -> 在最后一个具体画面处戛然而止 | 中（具象细节驱动） | 严禁段尾升华与金句感悟；控制破折号与四字修饰语堆叠 | 依靠具体名词与感官细节；删去 `Ultimately, this reminds us...` 类结语 |
| **S4：规格对照 + 覆盖诚实（Technical Spec）** | 能力范围表 -> 显式不支持清单 -> 退出码/失败模式 -> 最小复现示例 | 极高（清单 + 代码块） | 术语统一、全角中文标点与代码反引号严格区隔 | 短句直陈行为；每个限制条件对应可验证断言 |

### 3.4 警惕并治理「二阶趋同（Second-Order Convergence）」

正向风格库若设计不当，会立刻掉进一个隐蔽陷阱：**当某套原本小众的高品位模板被广泛分发后，千百个 Agent 反复套用同一套骨架与语气，小众模板本身就在几个月内异化为新一轮可一眼识破的 AI 味。** 2025–2026 年间，海外写作圈泛滥的“极短句断言体”和前端圈泛滥的“暖米白朱砂红卡片”就是现成教训。

应对二阶趋同需要四道工程防线，而不能靠呼吁用户「多发挥创意」：

1. 多轴正交组合（Combinatorial Composition）：不把风格封装成僵化的单一整块预设，而是将「结构骨架（S1–S4）× 信息密度 × 视角距离 × 视觉谱系」拆成可独立组合的维度，降低不同用户输出落入同一模板的概率。
2. 仓内跨文档趋同遥测（Intra-Repo Homogenization Detection）：单篇文章看不出套路，连续五篇文章一目了然。通过纯确定性脚本扫描同一目录的历史文稿，统计段首句式重复率、标题结构熵、相同过渡词复用率与句长分布坍缩度；一旦连续多篇滑入同一套路，主动报出「自我趋同提示」。
3. 一手事实与立场的强前置（Evidence-First Grounding）：文风只是放大器，真正不可被统计均值吞噬的差异化来自具体样本量、真实失败现场、明确反直觉取舍和作者独有的经验边界。在生成上下文中把「输入一手观测与反例」设为必填槽位，缺素材时显式标缺，绝不靠修辞注水填满篇幅。
4. 反漫画化配额与模板热度标记（Anti-Caricature Caps）：在 `dislop.voice/1` 与 `dislop.taste/1` 中写入反向护栏（例如规定短句占比上限、单篇破折号上限、同一开篇骨架不得在连续 3 篇中重复），并对社区高频下载的公开预设标注 `adoptionRisk`，提示用户在公开模板基础上叠加自己的本地参数微调。

### 3.5 补充演进（2026-11-23）：去不粘锅双轴定位与四级文风建模技术选型

在通用办公与编码 Agent（如 WorkBuddy、Claude Cowork、Codex）把 85 分标准化输出迅速商品化之后，“剥离后训练防御对冲（去不粘锅）+ 注入个人文风（`dislop.voice/1`）”构成长期差异化双主轴（详细证据见 [agent-repair-boundaries-eval-and-dehedging.zh-CN.md](./agent-repair-boundaries-eval-and-dehedging.zh-CN.md)）。不做基础大模型的前提下，个人文风建模沿四级谱系保持克制演进。

当前基座落地的是 **L1 确定性文体计量**：通过 `dislop.voice/1` 离线提取句长分布、标点频谱、连接词克制度与个人禁忌，在 `< 15ms` 内完成零上传抽取与改后语域漂移门禁。近期增量聚焦 **L2 风格嵌入与少量脱敏锚点检索**：参考 *RAGs to Style*（ACL 2024）与 *TinyStyler*，按体裁动态挂载 2–3 段经作者确认的短锚点片段进上下文，并加反漫画化配额抑制长上下文下的 style collapse。

更靠后的两条路径严格限定边界。**L3 推理期回溯与无监督对数概率重排**（*Antislop Sampler* `arXiv:2510.15061` 与 *OSST*）依赖底层采样或 token 对数概率，仅适合后续对接本地小模型探索，不绑死在商业闭源聊天接口上。**L4 轻量参数调制与外科微调**（*StyleAdaptedLM*、*AuthorMix* 2026-03、*HyperStyler* 2026-05 约 `2.4%` 参数开销，以及降低约 `90%` slop 且不伤 MMLU/GSM8K 的 *FTPO* `arXiv:2510.15061`）验证了低成本适配可行性，留待高客单企业云端定制阶段再按需评估。

在语料来源上，`dislop.voice/1` 还需要克服“成稿 AI 污染悖论”——随着公开发布的成稿普遍经过大模型润色，只读成稿会滑向递归均值坍缩。因此，个人文风提取的语料源头应从“历史成稿”向前延伸到**未受 AI 润色污染的本地原始人类输入**：纯用户侧手写 Prompt 与语音口述转写（剥离模型回复）、未修饰的同行技术讨论与评审批注，以及人工否决或修改 AI 草稿的 Diff 轨迹。依托纯本地离线零上传能力，工具得以在不触碰云端隐私红线的前提下，将最私密的高熵原始输入脱噪编译为可用、可检验的 `.dislop.local/voice.json` 风格边界。

## 4. 双引擎协同架构与 `dislop` 产品化落地方案

### 4.1 架构定力：为什么 `dislop` 必须坚持「零 LLM 核心 + 双向协同」

结合 [anti-slop-landscape-2026.zh-CN.md](./anti-slop-landscape-2026.zh-CN.md) 与 [ROADMAP.zh-CN.md](../../ROADMAP.zh-CN.md) 的生态判断，`dislop` 当前最稳固的护城河在于：**零第三方运行时依赖、默认零上传隐私保证、Node + Python 双端一致的 7 套内置规则包与 53 条反模式库、随包 `14.6 KB` Pocket ML 以及办公交付物（`.docx`/`.pptx`）去 AI 味体检**（不做 `.pdf` 印前预检或独立 `dislop verify` diff 命令，数字保真作为自动改写时的内部护栏）。

因此，引入「反趋同与正向差异化」方向时，**绝不能**把 `dislop` 变成内置大模型 API Key、替用户生成全文的膨胀套壳应用。正确的双引擎协作边界是：**生成交给人类或外部宿主 Agent（Claude Code / Codex / Cursor），`dislop` 垄断「正向规格编译 + 确定性声纹/设计提取 + 负向与正向双轨验收」**：

```text
                       ┌───────────────────────────────────────────────┐
                       │   正向牵引引擎 (Positive Pull · 确定性协议层)    │
                       │  · dislop voice extract（本地历史稿统计画像）    │
                       │  · Taste Card (`dislop.taste/1`) 正向设计文法   │
                       │  · Brief Compiler（反默认禁令 + seed 发散约束） │
                       └───────────────────────┬───────────────────────┘
                                               │ 输出紧凑结构化 Context
                                               ▼
                       ┌───────────────────────────────────────────────┐
                       │   外部创作层 (人类作者 / 宿主 Agent / Skills)    │
                       │  · Verbalized Sampling / 正交骨架生成 2–3 候选  │
                       │  · 严格带入一手观测、真实数值与边界条件           │
                       └───────────────────────┬───────────────────────┘
                                               │ 提交 2–3 份候选稿
                                               ▼
                       ┌───────────────────────────────────────────────┐
                       │   负向防线与比选引擎 (dislop Core · 零 LLM)     │
                       │  1. core 客观底线门禁（路径/占位/对比度/越界）    │
                       │  2. verify 事实锁定与二阶口号漂移拦截            │
                       │  3. compare 声纹区间偏差 + Taste 断言 + 候选差异 │
                       │  4. drift 跨文档自我趋同度巡检                   │
                       └───────────────────────┬───────────────────────┘
                                               │ 输出比选清样表
                                               ▼
                             人类作者 10 秒完成最终品味拍板并交付
```

这套双引擎设计把两项原本割裂的能力拧成一条高内聚工程链路：负向防线（`core` + 反模式规则 + `verify`）兜住下限，确保发散绝不牺牲事实与交付质量；正向牵引（`taste` + `voice` + `brief` + `compare`）拉升上限，解决「删完套话之后依然平庸像模板」的根本痛点。

### 4.2 五个核心产品模块与接口设计

全部模块沿用 `src/core.mjs`（零依赖 ES 模块）与 `src/dislop/`（Python 标准库）双运行时同源设计，保证 CLI、MCP 与浏览器工作台行为一致：

| 模块 | 新增协议 / 命令 / MCP 接口 | 确定性实现职责（零 LLM） | 解决的真实痛点 |
|---|---|---|---|
| **1. 正向协议层** | `dislop.taste/1`（设计参考卡）与 `dislop.voice/1`（声纹画像）；完全向后兼容现有 `dislop.pack/2` | 将版面网格、字族角色、色彩预算、句长 $CV$ 区间、标点频谱与反默认禁令写成可校验 JSON | 告别靠散文式 Prompt 碰运气，使正向审美规则可版本化、可复用、可单元测试 |
| **2. 离线声纹提取器** | CLI: `dislop voice extract <dir> -o .dislop.local/voice.json`<br>Browser: 清样工作台本地拖拽解析 | 纯本地统计 5–20 篇历史 `.md`/`.txt`/`.docx` 的句长分布、$CV$、段长、标点频谱、连接词频与中英混排特征 | 零上传保护个人/企业私密语料，用客观数据替代写作者失真的自我描述 |
| **3. 可控发散上下文编译器** | CLI: `dislop brief --taste <id> --voice <path> --seed <n>`<br>MCP: `dislop_taste_context` | 按目标媒介与确定性种子拼装紧凑生成约束包：目标声纹区间 + 反默认禁令 + 正交骨架选项 + 受保护事实清单 | 让宿主 Agent 一键执行 Verbalized Sampling 与多路径发散，而不向模型倾倒冗长禁词表 |
| **4. 多候选比选与正向校验** | CLI: `dislop compare a.md b.md c.md --against src.md --voice ...`<br>MCP: `dislop_compare` | 并行对多份候选跑 `core` 过关校验 + `verify` 事实保真 + `voice` 目标区间偏离度 + `taste` 静态设计断言 + 候选间 n-gram/结构差异度 | 把「多路径发散」后的审阅成本从通读 3 篇全文降为核对 1 张客观记分清样表 |
| **5. 仓内趋同度巡检** | CLI: `dislop drift <dir>` | 扫描同目录多篇已发/待发文档的段首重复度、标题模板熵、列表墙比例与句长分布坍缩，标记二阶自我趋同 | 防止团队把某张优秀 `taste` 或 `voice` 卡用成千篇一律的新模板 |

在交付形态分工上，四个入口各有明确边界：
- `CLI`（`bin/dislop.mjs` / `dislop`）：面向 CI 流水线、本地 Git 钩子与开发者脚本，已落地 `dislop voice` 离线声纹提取，后续可按需扩展 `brief`、`compare`、`drift`。
- `MCP`（`dislop-mcp`）：面向 Claude Code、Codex、Cursor 等读写 Agent，在现有 7 个离线工具（已含 `dislop_voice_extract_offline`）基础上按需评估正向约束扩展。
- `Agent Skill`（`SKILL.md` + `./references/`）：封装写作规约与检查剧本，解决纯 MCP 依赖 Agent 主动调用的触发率问题。
- `静态浏览器清样工作台`（`site/`）：严守 `CSP: connect-src 'self'`（离线检查 0 上传），已内置纯前端离线声纹体检抽屉，让非终端用户贴入历史文章即可生成 `dislop.voice/1`。

### 4.4 版权、归因与隐私合规硬边界

正向参考体系比纯负向规则更容易触及知识产权与数据隐私敏感区，必须在协议层与工程层预先写死五条红线：

1. 严守「抽象文法 vs. 具体表达」法律分界：依据美国版权局一贯立场与国际通行的思想-表达二分法（idea-expression dichotomy），抽象排版网格、色阶比例与修辞结构不受版权垄断，但第三方网站的具体文案、受版权保护的插画/图标、付费字体文件以及具备来源识别性的商业外观（Trade Dress）受版权或反不正当竞争法保护。因此，所有 `dislop.taste/1` 卡片只能编码抽象比例、令牌约束与设计原则，并保留一手出处链接归因，严禁复制第三方站点完整 DOM/CSS 源码、截图或商业字体。
2. 禁止「实名人物与商业品牌冒名仿写/拟态」预设：公开仓库不内置任何「一键模仿某位在世或已故作家、学者、记者或商业品牌」的预设包；所有官方内置正反范本均须采用原创构造、公有领域文本或明确兼容开源许可证（如 MIT / Apache-2.0 / CC-BY）材料，并在 JSON 中强制声明 `source` 与 `license`。2026 年 3 月，Grammarly / Superhuman 因未经授权抓取名家作品推出模拟作家与学者审稿的 `Expert Review`，遭调查记者 Julia Angwin 在纽约南区联邦法院提起集体诉讼（*Angwin v. Superhuman Platform, Inc.*）并被迫公开致歉下架（详见 [grammarly-evolution-and-agent-lessons.zh-CN.md](./grammarly-evolution-and-agent-lessons.zh-CN.md)），这是最直接的前车之鉴。
3. 尊重一手参考源条款与访问礼仪：正向参考索引（如 [verified-positive-sources.json](./positive-divergence/verified-positive-sources.json)）仅记录公开首页 URL、客观分类标签与简短结构观察，不做自动化整站抓取或图片镜像，严格遵守站点 `robots.txt` 与限流策略。
4. 个人声纹语料物理留在本地：`dislop voice extract` 处理的用户历史文章、会议纪要与内部文档默认只输出统计画像与经用户审核的脱敏短片段，落盘路径默认指向被 `.gitignore` 忽略的 `.dislop.local/voice.json`，零网络外发；提交前由 `dislop core` 检查拦截误入公开仓库的私有路径与敏感词。
5. 诚实表达与监管透明并行：延续本仓库在 [anti-slop-landscape-2026.zh-CN.md](./anti-slop-landscape-2026.zh-CN.md#12-监管与平台透明度坐标20252026) 确立的伦理底线，正向差异化与声纹校准服务于提升信息密度、可读性与审美辨识度，绝不提供「伪造错别字绕过检测」或规避中国《人工智能生成合成内容标识办法》（GB 45438-2025）及欧盟 EU AI Act 第 50 条透明度标识义务的功能。
