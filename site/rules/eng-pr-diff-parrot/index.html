eng-pr-diff-parrot 研发文档与复盘 (engineering-spec) warning markdown, text Markdown card
判断方法

删掉套话壳，直接写出关联问题单、改动前后的具体行为差异及验证方法。

这条规则查什么

空泛的 AI 提交摘要只重复“通过优化提升可维护性”，未说明具体修掉的缺陷、边界条件或单号。

原句与改法对照

原句（会标出问题）
本次 PR 旨在通过重构连接池管理逻辑进一步提升系统的稳定性与可维护性。
换了种 AI 味
这不是一次普通的代码重构，而是连接池稳定性的底层重塑。
改干净的版本
修复连接池重连分支未释放旧句柄导致的连接泄漏，避免长运行后连接耗尽。

改法要点： 点明具体的泄漏触发分支与直接后果，不写空泛的稳定性套话。
